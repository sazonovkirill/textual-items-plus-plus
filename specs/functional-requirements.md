# Functional Requirements

- Status: Draft
- Last updated: 2026-10-13

What textual-items++ does, as stated by the owner on 2026-10-13. The owner's answers are recorded under [Decisions](#decisions) and referenced as **(D-n)**; the questions in [open-questions.md](open-questions.md), referenced as **(OQ-n)**, were all decided on 2026-10-13, and each records its decision there.

Priorities: **Must** is required for v1, **Should** is expected soon after, **Later** is planned after v1 and must not be precluded by the design, **Won't** is out of scope.

Requirement IDs have the form `FR-<AREA>-<nn>` and are stable: never renumber or reuse one; mark a dropped requirement **Won't** instead. `bash app/scripts/validate.sh trace` reads the Must rows of these tables ([testing strategy](../docs/testing-strategy.md#traceability)).

References: [Things 3](reference/things3.md), [Todoist](reference/todoist.md), [TaskPaper](reference/taskpaper.md), [Workflowy](reference/workflowy.md), [TUI best practices](reference/tui-best-practices.md) and the owner's earlier app, [taskpaper-terminal](reference/taskpaper-terminal/README.md), whose setups this app copies where a requirement says so.

## Product summary

textual-items++ is a keyboard-first todo app for the terminal, in the spirit of Things 3 and Todoist, for software engineers and other people who live in a terminal. Work is organized as areas, projects, sections and tasks, as in Things 3, with two changes: areas can hold sections, and sections have descriptions; projects do not nest (D-2, D-75). Titles, dates and descriptions are edited in place, as in Things 3; every item's notes and comments, and a task's checklist, open in a full-height panel on the right, as in taskpaper-terminal (D-27, OQ-6). Everything is stored in one plain-text `.taskpaper` file (D-6). The look, keys and settings follow taskpaper-terminal (D-8).

## Terms

- **Area**: a top-level area of responsibility, such as Work or Home, that groups projects, sections and tasks; unlike a project it has no tags or dates (FR-ORG, D-75).
- **Project**: a goal made of tasks; it sits in an area or at the top level and holds no other projects (FR-ORG, D-75).
- **Section**: a titled group of tasks inside an area or a project, like a heading in Things 3 (FR-ORG).
- **Task**: one thing to do, with a title and optional description, notes, comments, start date, due date and checklist (FR-TASK).
- **Container**: an area, project or section, or the Inbox: anything a task can be in.
- **Item**: an area, project, section or task.
- **Checklist item**: one line of a task's checklist; checklist items nest to any depth (FR-CHK).
- **Description**: Markdown text of any item, shown inline under its title (D-27).
- **Attachments**: an item's notes and comments, shown in the attachments panel, as in taskpaper-terminal (FR-ATT, D-27).
- **Note**: Markdown text attached to any item, kept in the attachments panel rather than inline (FR-ATT).
- **Comment**: a dated one-line remark on any item, as in Todoist but for one user (FR-ATT).
- **Inbox**: the built-in place for tasks not yet organized (FR-ORG-07).
- **View**: a list the app builds, such as Inbox, Today, Upcoming, Flagged, All, Logbook, Trash or search results, as opposed to a container shown as itself.
- **Pane**: one column of the split view, showing its own view or container (FR-PANE).
- **Navigate mode** and **edit mode**: in navigate mode keys act on items; in edit mode keys edit the text of one item in place (FR-EDIT).
- **Start date**: the day an item becomes relevant, Things 3's "When". **Due date**: the day it must be done, Things 3's "Deadline". Any item can have either or both (D-13).
- **Tag**: a label the user attaches to any item, as in Things 3 (D-12).
- **Later**: a mark on a task or project the user has put off, as Things 3's Someday (FR-ORG-11, D-89).
- **Evening**: the part of Today, after the rest, holding the items the user has put off until later that day, as Things 3's This Evening (FR-VIEW-13, D-99).
- **Flagged**: a mark on a task or project the user holds important, shown as a red flag (FR-ORG-12, D-101).

## FR-ORG · Organization

| ID | Requirement | Priority |
|---|---|---|
| FR-ORG-01 | Areas sit at the top level and contain projects, sections and tasks, in an order the user sets. Areas do not nest, and are not completed and take no tags or dates (OQ-1, D-75, D-81). | Must |
| FR-ORG-02 | Projects sit in an area or at the top level, and contain sections and tasks (D-2). Projects do not nest: the data model and the file keep a project inside another, as a file from another editor may hold, but nothing in the app puts one there (D-57, D-75). | Must |
| FR-ORG-03 | Sections sit in an area or a project, unlike Things 3, where areas cannot have headings, and contain tasks (D-2). | Must |
| FR-ORG-04 | Tasks sit in the Inbox, an area, a project or a section. | Must |
| FR-ORG-05 | Every area, project and section has a title, an optional description (FR-ORG-10) and optional attachments, notes and comments (FR-ATT); sections have descriptions, unlike Things 3 (D-2, D-27). Projects and sections also have an optional start date, due date and tags (FR-DATE, FR-TAG); areas have none (D-75). | Must |
| FR-ORG-06 | The user creates, renames, reorders, moves and deletes areas, projects and sections. Moving or deleting one carries everything inside it. An area holding no project can be turned into a project, but a project can't be turned into an area (D-25, D-75); a section can be turned into a project and back, keeping their contents where the target allows them (OQ-2). | Must |
| FR-ORG-07 | The Inbox is a built-in container, always first, where tasks go when no other place is chosen, as in Things 3. It holds tasks only (OQ-3). | Must |
| FR-ORG-08 | Items keep the order the user gives them everywhere; nothing is sorted automatically except in views that say so. | Must |
| FR-ORG-09 | A project or a section can be completed as well as a task; an area cannot, and is only deleted (D-81). Completing an item leaves everything inside it in its own state, uncompleted items included. The completed item itself is shown like any other completed item (FR-VIEW-03, FR-VIEW-11), but everything inside it, completed or not, is no longer shown anywhere in the app: not in any view, the Logbook and search included, nor in palettes, pickers, the Navigator, the sidebar or the item opened as a container. Uncompleting the item shows it all again (OQ-4). Completing a project that still holds open tasks asks to confirm first (D-140). | Must |
| FR-ORG-10 | Every item, area, project, section or task, has an optional description: Markdown text of any length shown inline and dimmed. Under a row in a list only its first line shows, wrapped or cut as FR-UI-05 says; an opened item shows it in full under its title. It is edited in place (D-27). | Must |
| FR-ORG-11 | A task or a project can be marked Later, as Things 3's Someday, and taken out of Later again with **Toggle Later** (`ml`), which acts on the whole selection at once, marking every item when one is not Later and otherwise taking them all out; an area or a section is never Later, and asking for it says so in the status line. A Later item is drawn dimmed and listed after the open items of its group, in its container and in the sidebar, and before the completed ones (FR-VIEW-11), without changing its place in the file; the file marks it `@later` (D-89). Everything inside a Later project counts as Later and is drawn dimmed too, without a mark of its own. Later and a start date exclude each other, as Things 3's When is either a day or Someday: marking an item Later clears its start date, and giving it one takes it out of Later (D-92). | Must |
| FR-ORG-12 | A task or a project can be flagged as important, and unflagged again, with **Toggle Flag** (`mf`), which acts on the whole selection at once, flagging every project and task in it when one is not flagged and otherwise unflagging them all; an area or a section is never flagged, and asking for it says so in the status line. A flagged item shows a red flag in front of its title, in its list, in the sidebar and in the Navigator, and the edit dialog flags and unflags it; the file marks it `@flagged` (D-101). | Must |

## FR-CHK · Checklists

| ID | Requirement | Priority |
|---|---|---|
| FR-CHK-01 | A task's checklist is a list of items, each with text and a done state, nested to any depth, unlike Things 3, whose checklists are flat (D-1). | Must |
| FR-CHK-02 | The checklist is shown and edited in the attachments panel, in a Checklist section between the notes and the comments (FR-ATT, OQ-6). | Must |
| FR-CHK-03 | Checklist items are added, edited, deleted, checked and unchecked, reordered with the same keys as items elsewhere, and indented and outdented with `]` and `[` or `Tab` and `Shift+Tab`, the only items that nest (D-75, D-104); while an item's text is edited, `Tab` and `Shift+Tab` indent and outdent it and editing goes on. | FR-CHK-04 | Checking an item does not check or complete anything else: its children, its parent and the task keep their own state. A checked item and everything under it, at any depth, are drawn dimmed, as taskpaper-terminal draws a done block and its contents (OQ-7). | Must |

## FR-OPS · Selection and rearranging

These copy taskpaper-terminal's selection and structural operations ([editing.md §4](reference/taskpaper-terminal/specs/editing.md#4-structural-operations-fr-ops), [navigation.md §2.1](reference/taskpaper-terminal/specs/navigation.md#21-selection-fr-ops-01), D-18).

| ID | Requirement | Priority |
|---|---|---|
| FR-OPS-01 | Several items are selected by extending the selection with `Shift` and a motion (`Shift+↓`/`Shift+↑`, `Shift+j`/`Shift+k`) (D-24), by toggling items one by one, as in taskpaper-terminal (D-18), or in a visual line mode, as vim's `V` starts, in which every motion extends (D-82). | Must |
| FR-OPS-02 | The focused item or the selection moves up and down among its siblings with `Alt` and a motion (`Alt+↓`/`Alt+↑`, `Alt+j`/`Alt+k`) (D-24), crossing into the neighboring container at the edges, carrying everything inside it (D-18). | Must |
| FR-OPS-03 | In the attachments panel, the focused checklist item is indented under the one above it with `]` or `Tab` and outdented out of the one holding it with `[` or `Shift+Tab` (D-24, D-104); an indent or outdent the checklist does not allow is refused with a short message. Only checklist items nest: elsewhere `]` and `[` nudge the start date (FR-DATE-06), and `Tab`/`Shift+Tab` cycle the panes (D-75, D-79, D-82). | Must |
| FR-OPS-04 | The focused item or the selection moves to another container chosen in a fuzzy picker (Move to), as in taskpaper-terminal (D-18, D-39). | Must |
| FR-OPS-05 | The selection is deleted, duplicated, copied, cut and pasted with its contents; pasted text with several lines becomes several items, as in taskpaper-terminal (D-18). | Must |
| FR-OPS-06 | Completing, setting dates, tagging and deleting apply to the whole selection at once (D-18). | Must |
| FR-OPS-07 | Group into section: the selected tasks become the tasks of a new section created where the first of them was, in the same area or project, whose title is then edited in place (D-25); it is refused with a message for tasks already in a section or in the Inbox, where a section can't go (OQ-2). | Must |
| FR-OPS-08 | Group into project: the selected tasks and sections become the contents of a new project created where the first of them was, whose title is then edited in place (D-25); it is refused with a message where a project can't go, in a section or the Inbox (OQ-2). | Must |
| FR-OPS-09 | Converting a project to an area: no command does it (D-25). | Won't |
| FR-OPS-10 | Tasks move between sections naturally, as in Things 3, although in the file a section is a TaskPaper project holding its tasks: on screen the tasks outside sections and the sections' tasks read as one list with section headings as dividers (FR-VIEW-05), so moving a task down past a heading puts it first in that section, moving the first task of a section up puts it last in the section above or, from the first section, last among the tasks outside sections, and moving the last task of the last section down does nothing. Move to lists sections as destinations. A section moves only among the sections, never above the tasks outside sections, and a child project only among the child projects. Multi-selections move the same way, and the file is rewritten to match (D-28). | Must |

## Out of scope

- Sync, sharing, collaborators and assignees: the app is for one user and one file (D-1).
- Reminders and notifications.
