# TUI Best Practices
- Status: Reference
- Last updated: 2026-10-13

This document collects practices from well-regarded terminal UIs, from Ratatui's own guidance, and from terminal specifications. It guides textual-items++, a Rust + Ratatui 0.30 + crossterm 0.29 todo app for software engineers. The app is keyboard first, with vi-style bindings, a command palette, a go-to-symbol palette, full-text search, multiple panes, inline editing, and a full-height notes and comments panel on the right.

Findings carry inline source links. Statements marked **(inferred)** are our own reasoning or synthesis, not a claim made by the source.

## 1. Exemplary TUIs and what they do well

### Ratatui's own recommendations
- **Ratatui 0.30 basics.** The crate is now split into `ratatui-core`, `ratatui-widgets`, `ratatui-crossterm` and others, and `ratatui` re-exports them for apps. Feature flags (`crossterm_0_28`, `crossterm_0_29`) pick the crossterm version. The release adds `ratatui::run()`, which runs `init()`, your closure and `restore()`. MSRV is 1.86 and the code uses the 2024 edition. `Alignment` was renamed `HorizontalAlignment`, and `Flex::SpaceEvenly` was added. [Ratatui v0.30 highlights](https://ratatui.rs/highlights/v030/)
- **The Elm architecture (TEA).** Keep all state in a `Model` and turn every input into a `Message` enum variant in one place (`handle_event` → `handle_key`). `update(&mut Model, Message) -> Option<Message>` can chain follow-up messages. The `view` is a pure function of the model. Treat transitions as a finite state machine. [Ratatui: The Elm Architecture](https://ratatui.rs/concepts/application-patterns/the-elm-architecture/)
- **Event handling.** Ratatui does not capture events itself. It describes three patterns: one central `match`, central capture that passes messages on (common with channels and threads), and distributed per-component loops. It recommends whichever fits the app. [Ratatui: Event handling](https://ratatui.rs/concepts/event-handling/)
- **Rendering.** Ratatui is immediate mode: every `terminal.draw` rebuilds the UI from state, and it "only updates when you tell it to". Never block the render thread. [Ratatui: Rendering](https://ratatui.rs/concepts/rendering/) Internally, `Terminal::draw` diffs the new `Buffer` against the previous one (`Buffer::diff`) and writes only the changed cells to the backend. [ratatui-core buffer.rs](https://github.com/ratatui/ratatui/blob/main/ratatui-core/src/buffer/buffer.rs)
- **Layout.** `Layout` splits a `Rect` using `Length`, `Min`, `Max`, `Percentage`, `Ratio` and `Fill` constraints, solved by Cassowary. Use `Flex` to place leftover space and `.spacing(n)` for gaps. Nest layouts for grids. Percentages are relative to the parent, so mixing them with fixed lengths can surprise you. [Ratatui: Layout](https://ratatui.rs/concepts/layout/)
- **Async.** The upstream `async-github` example runs network work on tokio tasks while the UI keeps drawing. [ratatui examples/apps](https://github.com/ratatui/ratatui/tree/main/examples/apps) Production Ratatui apps such as taskwarrior-tui use crossterm's `event-stream` feature, which provides an async `EventStream`. [taskwarrior-tui Cargo.toml](https://github.com/kdheepak/taskwarrior-tui/blob/main/Cargo.toml)

Control is keyboard only, help is shown in context, and vim bindings come from a key config file. | [btop](https://github.com/aristocratos/btop) | C++ | Dense dashboards with optional mouse support, a `vim_keys` option, themes, truecolor with a low-color (256) fallback, and a TTY mode for 16-color consoles. |

| [posting](https://github.com/darrenburns/posting) | Python, Textual | Command palette, a "jump mode" that labels every focusable widget so a keypress moves focus there, vim keys, user themes, and it works over SSH. |
| [harlequin](https://github.com/tconbeer/harlequin) | Python, Textual | An IDE-style layout with a catalog, an editor (`textual-textarea`) and a results grid. Key bindings are customisable and connections are stored as profiles. |

| [superfile](https://github.com/yorukot/superfile) | Go, Bubble Tea v2 | A multi-panel file manager with Nerd Font icons that a config flag can turn off. |

**Common threads (inferred):** every app above can be fully driven from the keyboard. Each has one key that reveals all keys (`?`), keeps a persistent hint line, and has a palette or command line for rare actions. Filtering happens live as you type, Esc always backs out one level, and slow work never blocks drawing.

## 2. Keyboard design

- **Vi motions.** `j`/`k` (down/up), `h`/`l` (out/in or left/right pane), `gg`/`G` (first/last), `Ctrl-d`/`Ctrl-u` (half page) and `/` (search) are the shared vocabulary of lazygit, k9s, telescope, taskwarrior-tui and yazi (sources above). Arrow keys and PgUp/PgDn should work as well. lazygit binds `K`, `J`, `Ctrl-u` and `Ctrl-d` alongside PgUp and PgDn.
- **Modal vs modeless.** Navigation-heavy apps are mostly modeless: a key always does the same thing in a given pane (lazygit, k9s). Text entry is the one real mode. atuin and telescope offer an explicit choice of `vim-insert` or `vim-normal` for the prompt. **(inferred)** A todo app should be modeless while navigating and switch to insert mode only while a text field is focused. The current mode must always be visible in the status line.
- **Leader and prefix keys.** helix groups pickers under `Space` and goto commands under `g`. which-key.nvim and helix's `auto-info` show the available continuations after a prefix. Neovim's `timeoutlen` defaults to 1000 ms. **(inferred)** Show the hint popup after about 300–500 ms so experts who type fast never see it, and keep sequences to two keys.
- **Discoverability.** Use `?` for a context help overlay (lazygit, k9s, telescope normal mode), a hint line for the current context (lazygit's options bar, Textual's `Footer`), and a command palette that lists every action (Textual, helix `Space ?`, posting). gitui puts its help in context so users "don't need to memorize" many keys.
- **Esc is consistent.** Esc cancels or leaves the innermost layer (lazygit: "Cancel"; k9s exits filter and command mode; telescope closes from normal mode). **(inferred)** Use a fixed ladder: close popup → clear filter or selection → leave insert mode → return focus to the main list. Esc never quits and never discards typed text without an undo.
- **Legacy terminal limits.** Under legacy encoding only Ctrl and Alt work reliably. `Ctrl+I` is the same as Tab, `Ctrl+M` is Enter, Ctrl+Shift combinations are unreliable, release and repeat events don't exist, and a lone Esc can only be told apart from an escape sequence by timing. [kitty keyboard protocol](https://sw.kovidgoyal.net/kitty/keyboard-protocol/)
- **The kitty protocol.** It uses progressive enhancement flags 1 (disambiguate), 2 (event types), 4 (alternate keys), 8 (all keys as escapes) and 16 (associated text). Apps push with `CSI > flags u`, pop with `CSI < u` and query with `CSI ? u`. Supported by kitty, Alacritty, foot, Ghostty, iTerm2, Microsoft Terminal, Rio, WezTerm and others (same source).
- **crossterm 0.29 support.** `PushKeyboardEnhancementFlags` / `PopKeyboardEnhancementFlags` cover the flags `DISAMBIGUATE_ESCAPE_CODES`, `REPORT_EVENT_TYPES`, `REPORT_ALTERNATE_KEYS` and `REPORT_ALL_KEYS_AS_ESCAPE_CODES`. Its docs note that alternate keys are "not yet supported by crossterm". `terminal::supports_keyboard_enhancement()` detects support and always returns `false` on Windows. [KeyboardEnhancementFlags](https://docs.rs/crossterm/latest/crossterm/event/struct.KeyboardEnhancementFlags.html), [crossterm source](https://github.com/crossterm-rs/crossterm/blob/master/src/terminal/sys/windows.rs) On Windows, crossterm reports both `Press` and `Release` events, so filter on `KeyEventKind::Press`.
- **macOS Option.** Option sends Alt only when the terminal is set up for it (iTerm2 "Esc+", Terminal.app "Use Option as Meta key", Alacritty `option_as_alt`, kitty `macos_option_as_alt`, Ghostty `macos-option-as-alt`). **(inferred)** Never make Alt the only way to reach an action.
- **tmux and terminal conflicts.** tmux holds `Ctrl-b` as its prefix by default, and many users remap it to `Ctrl-a` or `Ctrl-Space`. Modified keys reach the app only with `extended-keys` (tmux 3.2+). [tmux Modifier Keys](https://github.com/tmux/tmux/wiki/Modifier-Keys) tmux 3.5 lowered the default `escape-time` from 500 ms to 10 ms, and older defaults cause a noticeable lag after Esc. [tmux CHANGES](https://github.com/tmux/tmux/blob/master/CHANGES) Terminal emulators also claim `Cmd`/`Ctrl+Shift+C/V/T/W` and similar keys. **(inferred)** Avoid default bindings on `Ctrl-a`, `Ctrl-b`, `Ctrl-Space`, `Ctrl-s`/`Ctrl-q` (XON/XOFF in cooked mode), `Ctrl-z` (suspend) and `Ctrl+Shift+*`.

## 3. Command palettes and fuzzy finders

- **nucleo.** This is the matcher Helix uses. `nucleo-matcher` (0.3.1) is the low-level, "finished" crate and the recommended replacement for `fuzzy-matcher` (last released 2020). `nucleo` (0.5.0) is a managed, multithreaded picker whose API may still change. It uses fzf's scoring with a two-matrix Smith-Waterman (affine gaps) that finds optimal alignments more often. It matches on graphemes and reports grapheme indices for highlighting. It is about 6x faster than skim/fuzzy-matcher, and in a 3-million-item demo it filtered in about one frame where fzf took about one second. [nucleo README](https://github.com/helix-editor/nucleo), [crates.io](https://crates.io/crates/nucleo-matcher)
- **fzf scoring constants.** Match 16, gap start −3, gap extension −1, boundary bonus 8, non-word bonus 8, camelCase/123 bonus 7, consecutive bonus 4, first-character multiplier 2, plus extra bonuses after whitespace and delimiters. [fzf algo.go](https://github.com/junegunn/fzf/blob/master/src/algo/algo.go) The result rewards matches at word starts, which suits titles like "Fix login bug" (`flb`).
- **Alternatives.** skim (5.7.x, actively released) is a full fzf-like tool and library. [skim](https://github.com/skim-rs/skim) frizbee (0.13) is a SIMD Smith-Waterman matcher with typo tolerance, used by blink.cmp. [frizbee](https://github.com/saghen/frizbee)
- **Match highlighting.** Textual's matcher highlights matched letters. nucleo returns indices so the UI can bold or colour them. **(inferred)** Map grapheme indices to `Span`s, so highlights stay correct for non-ASCII text.
- **Recency and frecency.** zoxide multiplies a counter by a recency factor: ×4 within an hour, ×2 within a day, ÷2 within a week, ÷4 after that. Old entries age out once the total passes a cap. [zoxide algorithm](https://github.com/ajeetdsouza/zoxide/wiki/Algorithm) **(inferred)** With an empty query, show recent commands and items first (Textual's `discover`). With a query, rank by fuzzy score and use frecency to break ties or add a small boost, so recency never overrides a clearly better match.
- **Show bindings in the palette.** Helix's and Textual's palettes list each command with its key binding, which teaches shortcuts over time. **(inferred)** Right-align the binding in a dimmed style.
- **Latency.** **(inferred)** Filtering should finish inside one frame (under 16 ms) for typical lists of up to 10k items. For larger sets, use `nucleo`'s background worker and redraw on its notify callback rather than matching on the input thread. Never debounce typing by more than one frame.
- **Prefixes.** **(inferred)** Use one palette with prefixes (`>` commands, `@` symbols, `#` tags, `/` full-text), the way VS Code-style palettes and k9s's `:` resource names do. Keep separate keys that open the palette with a prefix already typed.

## 4. Layout and visual design

- **Hierarchy without boxes.** **(inferred, from lazygit, helix and Things-style UIs)** Show hierarchy with weight (bold titles), dimming (`Modifier::DIM` or a muted foreground for metadata) and a single accent colour for the focused pane, rather than boxing every widget. Use borders to separate panes and whitespace to separate items. Ratatui 0.30 adds border merging, which makes collapsed shared borders easy. [v0.30 highlights](https://ratatui.rs/highlights/v030/)
- **Rounded borders.** `BorderType::Rounded` is common in modern Ratatui apps (gitui, atuin). **(inferred)** It is a style choice, but use it consistently and fall back to `Plain` in ASCII mode.
- **Focus indication.** **(inferred)** Show focus at least two ways: an accent-coloured border or title on the focused pane, plus a highlighted row (reversed or accent background) in the focused list. Dim the selection in unfocused panes so it stays visible without competing.
- **Status line and breadcrumbs.** k9s shows a breadcrumb row (resource › namespace). lazygit shows a context options bar. **(inferred)** Keep one bottom line for mode, breadcrumb (Area › Project › Heading), counts and transient messages, and a key-hint area that changes with focus.
- **Responsive at 80x24 and smaller.** atuin's `style = auto` switches to compact when the terminal is short. **(inferred)** Design for 80x24 first. Below about 100 columns, collapse the right notes panel into an overlay or toggle. Below about 60 columns, show one pane at a time. Below a hard minimum, render a "terminal too small" message rather than panicking on a zero-size `Rect`.
- **Nerd Font icons.** Nerd Fonts patch thousands of glyphs into fonts. [nerd-fonts](https://github.com/ryanoasis/nerd-fonts) lazygit (`gui.nerdFontsVersion`), superfile and yazi make icons optional. **(inferred)** Default to plain Unicode (✓ • ▸ ★), offer Nerd Font icons as opt-in, and offer ASCII as a last resort.
- **Colour depth.** VTE, Konsole and iTerm2 set `COLORTERM=truecolor` (or `24bit`), but the variable is not forwarded over ssh or sudo by default. Terminal.app, the Linux console and some others lack truecolor. [termstandard/colors](https://github.com/termstandard/colors) Neovim turns on `termguicolors` only when it can detect 24-bit support. [Neovim 0.10 news](https://github.com/neovim/neovim/blob/master/runtime/doc/news-0.10.txt) btop falls back to 256 and 16 colours. **(inferred)** Build themes from semantic tokens. Use 24-bit when `COLORTERM` says so, otherwise the 256-colour palette, and offer a 16-colour ANSI theme that inherits the user's terminal palette.
- **NO_COLOR.** When `NO_COLOR` is "present and not an empty string", suppress colour by default. Explicit user config overrides it. [no-color.org](https://no-color.org/) **(inferred)** In no-colour mode, keep the hierarchy through bold, dim, reverse and underline.
- **Light/dark detection.** `OSC 10 ; ?` and `OSC 11 ; ?` query the terminal's foreground and background (reply `rgb:RRRR/GGGG/BBBB`). [xterm ctlseqs](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html) Neovim sets `'background'` from this at startup. [Neovim options](https://github.com/neovim/neovim/blob/master/runtime/doc/options.txt) The `terminal-colorsaurus` crate (1.0.x) implements the query with timeouts. [crates.io](https://crates.io/crates/terminal-colorsaurus) **(inferred)** Query once before entering raw-mode rendering, time out within about 100 ms, and allow `theme = light|dark|auto`.

## 5. Performance and responsiveness

- **Render on events.** Ratatui draws only when asked, and the Elm example blocks on `event::poll` / `read` between frames ([TEA](https://ratatui.rs/concepts/application-patterns/the-elm-architecture/)). **(inferred)** Redraw only after an input event, a background-task message, a resize, or an active animation tick. When idle, CPU use should be about 0%.
- **Frame budget.** **(inferred)** Aim for a key-to-paint time of 16 ms or less (one 60 Hz frame). Keep `view` free of allocations that grow with dataset size. Precompute derived lists in `update`, not `view`. tachyonfx's examples poll on a 16 ms timeout only while effects run. [tachyonfx](https://github.com/ratatui/tachyonfx)
- **Synchronized output (DEC 2026).** `CSI ? 2026 h` (begin) and `CSI ? 2026 l` (end) make the terminal hold the last complete frame while an update streams, which prevents tearing. Support can be queried with `CSI ? 2026 $ p`. Supported by Windows Terminal, kitty, WezTerm, iTerm2, foot, Alacritty ≥ 0.13, Ghostty, tmux and others, but not VTE/GNOME Terminal at the time of the list. [Synchronized output spec](https://gist.github.com/christianparpart/d8a62cc1ab659194337d73e399004036) crossterm exposes `terminal::BeginSynchronizedUpdate` and `EndSynchronizedUpdate`. Ratatui's `draw` does not emit them itself (checked in the ratatui source, 0.30). **(inferred)** Wrap `terminal.draw` in these commands. Unsupported terminals ignore them.
- **Avoid flicker.** Rely on Ratatui's buffer diff. Avoid `terminal.clear()` except after a resize or when returning from a suspended external editor. Textual reaches the same result by compositing layers into one write per line. [Textual blog](https://textual.textualize.io/blog/2024/12/12/algorithms-for-high-performance-terminal-apps/)
- **Virtualised lists.** **(inferred)** Ratatui's `List` and `Table` take all items you pass and scroll with `ListState`/`TableState` offsets. For thousands of tasks, build `ListItem`s only for the visible window (offset .. offset + height) and keep your own scroll state.
- **Background I/O.** yazi (async I/O, cancellable prioritised tasks) and gitui (async git API) keep the UI live during slow work, and the gitui benchmark shows the memory cost of not doing so. **(inferred)** Run SQLite writes, sync and search-index updates on a worker (tokio task or thread) and send results back as `Message`s. Search results carry a query generation number, and stale results are dropped.
- **Startup time.** **(inferred)** Draw the first frame from cached or minimal state within about 50 ms. Load heavy indexes (full-text, symbol lists) lazily in the background, and show a dim "indexing…" hint until they are ready.

## 6. Text input

- **Crates and their maintenance (crates.io, 2026-10-13).**
  - `tui-textarea` (rhysd) was last released as 0.7.0 on 2024-10-22 and has no Ratatui 0.30 release. [crates.io](https://crates.io/crates/tui-textarea)
  - `ratatui-textarea` 0.9.3 (2026-10-05) lives under the `ratatui` GitHub org and is a "Ratatui fork of tui-textarea and maintained independently". It provides multi-line editing, Emacs shortcuts, undo/redo, soft wrap (character and word), regex search, selection and yank, and ships a vim state-machine example. gitui uses it. [ratatui-textarea](https://github.com/ratatui/ratatui-textarea)
  - `tui-textarea-2` 0.13.2 is another maintained fork with "ratatui 0.30+ support". [tui-textarea-2](https://github.com/srothgan/tui-textarea)
  - `edtui` 0.11.7 is a vim-modal editor widget built for embedding in Ratatui apps. [edtui](https://github.com/preiter93/edtui)
  - `tui-input` 0.15.5 is a lightweight single-line input. [tui-input](https://github.com/sayanarijit/tui-input)
  - **(inferred)** Use `ratatui-textarea` for notes and comments, and `tui-input` or a small in-house line editor for inline task-title editing and palette prompts.
- **Cursor rendering.** Use `frame.set_cursor_position` to place the real terminal cursor while editing ([TEA page](https://ratatui.rs/concepts/application-patterns/the-elm-architecture/) notes cursor placement in `view`). **(inferred)** A real cursor shows the user's chosen cursor shape and blink, and it anchors IME candidate windows. Switch the shape with crossterm `SetCursorStyle` (bar in insert mode, block in normal mode), and restore it on exit.
- **Unicode width and graphemes.** Width in cells is not the number of `char`s. CJK and most emoji take 2 cells, and combining marks take 0. Use `unicode-width` (0.2.x) to measure and `unicode-segmentation` (1.13.x) for grapheme-safe cursor movement and deletion. Backspace removes one grapheme, not one `char`. gitui uses both crates plus `unicode-truncate`. [gitui Cargo.toml](https://github.com/gitui-org/gitui/blob/master/Cargo.toml) Even Ratatui's diff has had wide-cell edge cases (yazi's fork branch, above). **(inferred)** Truncate titles by display width and end them with `…`.
- **Bracketed paste.** crossterm `EnableBracketedPaste` delivers a paste as one `Event::Paste(String)` rather than many key events. [crossterm event.rs](https://github.com/crossterm-rs/crossterm/blob/master/src/event.rs) **(inferred)** Without it, a pasted newline would submit the field and pasted `j`/`k` would run as commands. Normalise CRLF line endings and strip control characters.
- **IME limits.** **(inferred)** Terminals handle IME composition themselves and send only committed text, so crossterm never sees preedit text. Place the real cursor at the insertion point so the candidate window appears in the right place, and don't treat non-ASCII input as a command key.

## 7. Mouse, accessibility, compatibility, terminal restore

- **Mouse is optional.** btop and yazi support the mouse, but every action also has a key. **(inferred)** Turn on `EnableMouseCapture` only behind a setting, or document that holding Shift while dragging keeps native text selection. Capture disables the terminal's own selection in most emulators.
- **Accessibility.** **(inferred)** Screen readers handle full-screen TUIs poorly, so convey state in text as well as colour (`[x]`, `!` for priority, a "3 overdue" count), honour `NO_COLOR`, provide a high-contrast theme, avoid blinking, and make animation optional. A plain CLI (`tip list`, `tip add`) is a useful accessible fallback.
- **tmux.** Enable `extended-keys` for modified keys. Truecolor through tmux needs `terminal-features ... :RGB` or `Tc`. Synchronized output works under tmux. [tmux Modifier Keys](https://github.com/tmux/tmux/wiki/Modifier-Keys), [sync spec](https://gist.github.com/christianparpart/d8a62cc1ab659194337d73e399004036)
- **SSH.** `COLORTERM` is not forwarded by default ([termstandard](https://github.com/termstandard/colors)). **(inferred)** Detection queries (OSC 11, `CSI ? u`, DECRQM) should time out quickly on high-latency links, and an explicit config value must override detection.
- **Windows Terminal.** crossterm uses the console API on Windows: no keyboard enhancement, and Press and Release events must be filtered ([crossterm source](https://github.com/crossterm-rs/crossterm/blob/master/src/terminal/sys/windows.rs)).
- **Restore the terminal on panic.** Save the original hook with `take_hook()`, then install a hook that leaves the alternate screen and disables raw mode before calling the original. [Ratatui: Panic hooks](https://ratatui.rs/recipes/apps/panic-hooks/) `ratatui::init()` installs exactly this hook, and it must be called after other panic hooks are installed. [ratatui init.rs](https://github.com/ratatui/ratatui/blob/main/ratatui/src/init.rs) **(inferred)** The hook must also pop keyboard enhancement flags, disable mouse capture and bracketed paste, and restore the cursor style, because `init()` doesn't know you enabled them. Do the same on `Ctrl-z` suspend and while running `$EDITOR`.

## 8. Animation

- tachyonfx (0.25.x, in the `ratatui` org) provides 50+ effects: fades, dissolves, sweeps and slides, with easing, sequencing, parallel composition, cell filters and a string DSL. Effects are created once and applied each frame by `process_effects(elapsed, frame.buffer_mut(), area)` after widgets render, so they post-process the buffer and never own state. [tachyonfx](https://github.com/ratatui/tachyonfx)
- **(inferred)** Keep effects short (150–300 ms) and use them only for state changes: a task completed and fading out, a panel sliding open, a toast. Never animate in a way that delays input. Keys pressed during an animation act immediately on the final state. Run the 16 ms tick only while an effect is active, and provide `animations = false` (also forced by `NO_COLOR` or a reduced-motion setting).

## 9. Checklist for textual-items++

1. Structure the app as TEA: one `Model`, one `Message` enum, a pure `view`, and all key mapping in one keymap module (Ratatui TEA).
2. Draw only on input, worker messages, resize or an active animation. Idle CPU should be about 0%. **(inferred)**
3. Wrap each `terminal.draw` in crossterm `BeginSynchronizedUpdate`/`EndSynchronizedUpdate`, and never call `clear()` during normal frames.
4. Budget 16 ms from key to paint. Derive filtered and sorted lists in `update`, and build `ListItem`s only for visible rows. **(inferred)**
5. Run storage, search indexing and sync on background tasks. Tag results with a generation number and drop stale ones. **(inferred)**
6. Bind vi motions (`j k h l gg G Ctrl-d Ctrl-u /`) and arrow and Page keys to the same actions.
7. Stay modeless while navigating, use insert mode only inside text fields, and always show the mode in the status line. **(inferred)**
8. Use `Space` as the leader, with a which-key popup after about 400 ms. Keep sequences to two keys at most. **(inferred, after helix and which-key)**
9. `?` opens a context help overlay generated from the live keymap, so it can never drift from the real bindings. **(inferred)**
10. Show a persistent key-hint line for the focused pane (lazygit options bar, Textual Footer).
11. Esc backs out exactly one layer: popup → filter → insert mode → main list. Esc never quits. **(inferred)**
12. One palette (`Ctrl-p` or `:`) with prefixes for commands, symbols (`@`), tags (`#`) and full text (`/`). Each row shows its key binding, dimmed and right-aligned. **(inferred)**
13. Fuzzy match with `nucleo-matcher` (or `nucleo` for large sets), highlight matched graphemes, and break ties by frecency.
14. Push kitty keyboard flags (`DISAMBIGUATE_ESCAPE_CODES`) when `supports_keyboard_enhancement()` returns true. Every default binding must still work without them.
15. Avoid default bindings on `Ctrl-a`, `Ctrl-b`, `Ctrl-Space`, `Ctrl-s`, `Ctrl-q`, `Ctrl-z`, `Ctrl+Shift+*` and Alt-only chords. **(inferred)**
16. Filter `KeyEventKind::Press` so that Windows and kitty release and repeat events don't fire twice.
17. Enable bracketed paste. A paste never triggers commands or submits a field.
18. Measure text with `unicode-width`, move the cursor and delete by `unicode-segmentation` graphemes, and truncate by display width with `…`.
19. Use `ratatui-textarea` for the notes and comments panel, and a light single-line input for inline title edits. Re-check maintenance before pinning versions. **(inferred)**
20. Place the real terminal cursor while editing (bar in insert mode, block in normal mode) and restore the cursor style on exit.
21. Show hierarchy with bold, dim and one accent colour. Draw borders only between panes. Mark the focused pane with an accent border or title and the selected row with a highlight. **(inferred)**
22. The layout works at 80x24. The notes panel collapses to an overlay below about 100 columns, one pane shows below about 60 columns, and a "too small" message appears below the minimum. **(inferred)**
23. Use semantic theme tokens with truecolor, 256-colour and 16-colour variants chosen via `COLORTERM`. A config value overrides detection.
24. Honour `NO_COLOR` (non-empty) and keep the hierarchy through modifiers. Never encode meaning in colour alone.
25. Detect light or dark with an OSC 11 query (about 100 ms timeout) before the first frame. `theme = auto|light|dark`.
26. Use plain Unicode glyphs by default, with Nerd Font icons opt-in and an ASCII fallback.
27. Mouse support is optional and off by default. Every mouse action has a key equivalent. **(inferred)**
28. Use `ratatui::init()` (or an equivalent hook) to restore the terminal on panic, and also pop keyboard flags and disable paste and mouse modes. Do the same around `$EDITOR` and `Ctrl-z`.
29. Animations (tachyonfx) last 300 ms or less, never block input, and can be turned off.
30. The first frame appears within about 50 ms. Load heavy indexes lazily, with a dim progress hint. **(inferred)**
